# Lumi Android — Comprehensive Audit

**Audited:** 2026-09-05  
**Scope:** Kotlin/Compose source, manifest and Gradle configuration, AI/voice/inference paths, persistence, bundled UI maps, unit tests, and Android lint.  
**Method limitation:** No device/emulator was connected and the folder has no usable `.git` metadata, so runtime permission flows, device-specific overlays, OEM behavior, and history/diff were not directly verified.

## Release decision

**Do not ship the current build.** It contains exposed production credentials, incomplete AI/TTS implementations, unsafe automatic interaction behavior, and 7 Android lint errors. The automated quality gate is red: **81 unit tests ran; 1 failed**.

## Validation results

## P0 — release blockers

1. **Cloud API secrets are hard-coded into the APK.**
   - **Evidence:** `app/src/main/kotlin/ai/lumi/LumiApplication.kt:20-29` initializes Groq, NVIDIA, and Mistral keys in source.
   - **Impact:** Anyone can extract the APK, abuse the provider accounts, incur charges, and potentially access account-level usage. Encrypting the copied values in `EncryptedSharedPreferences` does not protect secrets already embedded in the APK.
   - **Fix:** Immediately revoke/rotate all exposed credentials. Remove bootstrap keys. Use user-supplied keys stored locally, or a backend-issued short-lived token with rate limiting and authentication. Add secret scanning to CI and prevent `local.properties` from being committed.

2. **The advertised on-device AI is a deterministic mock, so it can guide users to the wrong control.**
   - **Evidence:** `app/src/main/kotlin/ai/lumi/inference/GenieXRuntime.kt:44-50,75-91` returns a canned “Pay button” result for every VLM request; all factory branches return `MockQairtRuntime`.
   - **Impact:** When cloud/UI-tree analysis fails, the app can place a cursor and optionally tap around the same fixed coordinates regardless of the actual screen. This is especially dangerous for payment, settings, and account flows.
   - **Fix:** Integrate a real runtime before enabling local inference. Until then, return an explicit unavailable result and disable automatic actions; never substitute a fake model response in production.

3. **Text-to-speech is also a mock, while the product promises spoken guidance.**
   - **Evidence:** `app/src/main/kotlin/ai/lumi/voice/KokoroTTS.kt:38-39,61-65` has no model/session and always returns empty PCM.
   - **Impact:** Guidance can be silent or inconsistent. This materially breaks the accessibility use case.
   - **Fix:** Use `SystemTTSWrapper` as the verified production fallback until Kokoro has a real model asset, inference runtime, audio-track output, language support, and device tests.

4. **The database is not encrypted, despite the backup-policy comment claiming it is.**
   - **Evidence:** `app/src/main/kotlin/ai/lumi/di/AppModule.kt:25-27` uses ordinary Room; `app/src/main/res/xml/backup_rules.xml:3-5` claims a Keystore-backed encrypted database.
   - **Impact:** Stored profile facts, form memory, task history, and embeddings are readable from a compromised/rooted device or backup/debug extraction path. The privacy claim is inaccurate.
   - **Fix:** Either implement SQLCipher/Room encryption with a Keystore-protected key and migration plan, or correct all privacy claims and do not store sensitive information. Do not retain Aadhaar, address, DOB, payment, or other high-risk values by default.

5. **Automatic taps can trigger high-impact actions on apps not in the small package denylist.**
   - **Evidence:** `app/src/main/kotlin/ai/lumi/engine/TaskEngine.kt:421-449` auto-taps resolved bounds/LLM coordinates; `:527-533` blocks only five package names.
   - **Impact:** The model/UI-map may tap send, delete, purchase, submit, permission, or authentication controls in unlisted financial, health, government, or messaging apps. Package names vary by bank/OEM and the denylist is not a security boundary.
   - **Fix:** Default auto-tap to off; require a per-action confirmation for any state-changing tap. Block by action/semantic risk as well as package. Never auto-tap payment, transfer, OTP, authentication, send, delete, submit, permission, install, or external-link controls. Add an explicit user-visible safety state and audit log.

6. **The Android quality gate is failing with errors that can cause crashes or incorrect initialization.**
   - **Evidence:** `app/build/reports/lint-results-debug.txt` reports:
     - `VoiceService.kt:313`: missing runtime `RECORD_AUDIO` permission check.
     - `ModelSelector.kt:33`: `Build.SOC_MODEL` is API 31 but minSdk is 29.
     - `AndroidManifest.xml:123`: WorkManager initializer conflicts with `Application` implementing `Configuration.Provider`.
     - `LumiAccessibilityService.kt:86`, `OverlayService.kt:92`, `TaskEngine.kt:110`: receiver-export flags incomplete on pre-33 paths.
   - **Fix:** Make lint errors zero before release. Use `ContextCompat.registerReceiver(..., RECEIVER_NOT_EXPORTED)`, guard `Build.SOC_MODEL` by API level, check/request microphone permission immediately before `AudioRecord`, and remove the manual WorkManager initializer metadata or correctly configure on-demand initialization.

## P1 — major functional and AI reliability problems

1. **Multi-step screen-change logic contains an impossible condition.**
   - **Evidence:** `TaskEngine.kt:159-175` first assigns `currentPackageName = newPackageName`, then tests `newPackageName != currentPackageName`.
   - **Impact:** That condition is always false once a non-null package changes. Plans may re-resolve the same step instead of advancing or may advance only through unrelated click events.
   - **Fix:** Save `previousPackageName` before updating; derive `packageChanged` once and use it consistently. Add state-machine tests for same-app navigation, app launch, back navigation, and initial launch.

2. **Task state is not concurrency-safe and cancellation does not cancel active work.**
   - **Evidence:** `activeJob` is declared in `TaskEngine.kt:61` but no assignment was found; inference, auto-tap, screen events, and receiver callbacks launch independent jobs on `engineScope`.
   - **Impact:** A cancelled task can still finish an old inference request, speak an old instruction, or auto-tap after a new task begins. Multiple accessibility events can schedule duplicate step advancement.
   - **Fix:** Create one task-scoped `SupervisorJob`, assign every task action beneath it, cancel-and-join it before starting/cancelling/replacing a task, and serialize events with a mutex/channel. Introduce task/session IDs and ignore stale results.

3. **Bundled-plan fallback is unsafe and not screen-specific.**
   - **Evidence:** `UIMapRepository.kt:88-101` merges every bundled screen's plan for a package when a perceptual hash misses; `TaskEngine.kt:259-265` uses it after launching an app.
   - **Impact:** An updated or unexpected PhonePe/WhatsApp screen can receive a sequence assembled from unrelated screens. The app may highlight or auto-tap irrelevant controls.
   - **Fix:** Do not use a package-wide fallback. Require a verified current-screen match plus app version and screen/element validation. On a miss, provide manual, confirmable guidance or stop safely.

4. **The model download implementation is not crash-safe and does not enforce integrity in every accepted path.**
   - **Evidence:** `ModelDownloadManager.kt:73-126` writes directly to the final model filename; `:139-154` accepts sideloads whenever the checksum is the placeholder `REPLACE_WITH_ACTUAL_SHA256`.
   - **Impact:** Process death can leave a corrupted final file. Placeholder hashes undermine model integrity and enable malformed/tampered model loading.
   - **Fix:** Require real SHA-256 values, download to a unique `.part` file, fsync/verify, then atomically rename. Persist download state, enforce size limits/content type, and clean stale parts on startup.

5. **Automatic Wi-Fi download tries every direct model rather than the selected device/language requirements.**
   - **Evidence:** `TaskEngine.kt:119-141` iterates all direct `ModelSpec` entries as soon as Wi-Fi is active.
   - **Impact:** Unexpected multi-GB storage/network use, device heat, battery drain, and confusing “offline-ready” expectations.
   - **Fix:** Download only user-approved `ModelSelector.requiredModels(tier, languages)` under WorkManager constraints, show size/consent/progress, and use resumable/background-safe work.

6. **Hindi-only model selection breaks the ASR pipeline; the existing test catches it.**
   - **Evidence:** `ModelSelector.kt:57-72` includes English Whisper only when English is selected, but `WhisperEngine` uses Turbo Whisper for language detection before routing. `ModelSelectorTest.kt:74-79` fails because Hindi needs both models.
   - **Impact:** Hindi-only offline users can lack the detector model and get blank/error recognition.
   - **Fix:** Make the language detector a required dependency for every supported offline language, update the model plan and tests, and only report “offline ready” after all runtime dependencies are verified.

7. **Cloud response extraction and JSON construction are brittle.**
   - **Evidence:** `AnthropicClient.kt:151-170,184-205,303-322` hand-builds JSON and extracts nested responses via regex.
   - **Impact:** Escaped text, tool/reasoning responses, provider schema changes, or multiple `content` fields can produce bad instructions or parse failures. Logs may include provider response details.
   - **Fix:** Use Moshi/Kotlin serialization request/response DTOs, strict schema validation, numeric coordinate bounds checks, a provider-specific adapter, and redacted structured logs. Add fixture tests for valid, malformed, escaped, refusal, and rate-limit responses.

8. **The “offline” UX is misleading.**
   - **Evidence:** No real VLM/TTS runtime is integrated; several model specifications/paths are placeholders; `KokoroTTS` has no bundled model; `GenieXRuntime` is mocked.
   - **Impact:** The UI/README can promise offline help while the app may require cloud ASR or produce a canned VLM answer.
   - **Fix:** Clearly label unavailable capabilities, add capability probing, and test each declared tier on physical target hardware before publishing offline claims.

## P1 — privacy, security, and platform policy

1. **Accessibility-tree and screenshots can be sent to third-party providers without a granular consent boundary.**
   - **Evidence:** `TaskEngine.kt:302-319` sends UI-tree data to cloud before local inference; `AnthropicClient.kt` sends screen images and full UI text to configured providers.
   - **Impact:** Screens may contain OTPs, balances, health data, chats, IDs, and credentials. Users need a clear, revocable choice per provider/data type, not only a broad adaptive-mode switch.
   - **Fix:** Add a clear consent screen, provider/data disclosure, “never send screen text/images” mode, redaction for passwords/OTP/credit-card patterns, an always-visible cloud indicator, and explicit blocklists for sensitive screen classes.

2. **Broad permissions are not adequately minimized or justified.**
   - **Evidence:** `AndroidManifest.xml:13-51` requests overlay, accessibility, media projection, query-all-packages, battery-optimization exemption, microphone, and media-images access.
   - **Impact:** This combination demands unusually high user trust and can create app-store policy risk. `QUERY_ALL_PACKAGES`, accessibility, and battery-exemption requests require narrow, defensible use.
   - **Fix:** Remove `READ_MEDIA_IMAGES` if MediaProjection is the only capture route; replace `QUERY_ALL_PACKAGES` with `<queries>` for supported packages; request each permission just-in-time with a visible benefit; avoid battery exemption unless a policy-eligible use case is proven.

3. **Dynamic receiver exposure is inconsistent.**
   - **Evidence:** `TaskEngine.kt:108`, `LumiAccessibilityService.kt:84` use `RECEIVER_EXPORTED` for internal actions; other branches omit flags.
   - **Impact:** Other apps may inject transcript/error/cursor broadcasts on supported OS versions, while older versions lack explicit protections.
   - **Fix:** Use app-private mechanisms where possible. Otherwise use `ContextCompat.registerReceiver` with `RECEIVER_NOT_EXPORTED` for all internal actions and explicit package/permission validation.

4. **Logging risks retaining sensitive user content.**
   - **Evidence:** `TaskEngine.kt:219`, `VoiceService.kt:206,360`, `MemorySystem.kt:37,87` log goals, transcripts, names, and form values; debug logging is enabled in debug builds.
   - **Impact:** Sensitive data can enter logcat, device bug reports, and developer tooling.
   - **Fix:** Remove/redact all user content and secrets from logs, introduce a structured privacy-safe logger, and add tests/CI scans that reject logging of transcripts, keys, and form values.

## P2 — UI, accessibility, and user experience

1. **The home-screen Auto-Tap control is disconnected from the real preference and contradicts its default.**
   - **Evidence:** `HomeScreen.kt:39` initializes a local `false` state only; `LumiPreferences.kt:68-69` defaults actual auto-tap to `true`; `TaskEngine.kt:421` reads the real preference.
   - **Impact:** The UI may show Auto-Tap off while the engine auto-taps. This is a high-severity trust and safety defect.
   - **Fix:** Remove the duplicate home toggle or bind it to a lifecycle-aware preference flow. Default it to off and require informed opt-in.

2. **Saved bubble-size settings are not applied.**
   - **Evidence:** `LumiPreferences.kt:54-55,105-107` stores size; `OverlayService.kt:103-118` always creates a 56dp bubble.
   - **Impact:** Settings do not do what they promise.
   - **Fix:** Observe `bubbleSizeDp`, resize/recreate the overlay safely, and test all three sizes with large font/display sizes.

3. **The overlay prompt card is not accessible enough for its target audience.**
   - **Evidence:** `OverlayService.kt:146-296` uses emoji/text glyphs as interactive controls (`➔`, `✕`) with no content descriptions, custom views, fixed text sizes, and an overlay that may sit over app controls.
   - **Impact:** TalkBack users cannot reliably discover actions; low-vision users may struggle; emoji/glyph rendering varies by device.
   - **Fix:** Use real `ImageButton`s with content descriptions and 48dp targets, semantic labels, scaled text, contrast checks, focus order, dismissible/non-obscuring placement, and TalkBack tests.

4. **Drag handling fails the accessibility click contract.**
   - **Evidence:** `OverlayService.kt:464` is reported by lint for not calling `View.performClick()`.
   - **Impact:** Assistive technologies may not activate the bubble consistently.
   - **Fix:** Detect a tap versus drag, call `performClick()` for taps, and implement `performClick()` on the custom bubble.

5. **Most UI strings are hard-coded in Kotlin and resources are largely unused.**
   - **Evidence:** `HomeScreen.kt`, `SettingsActivity.kt`, `OverlayService.kt`; lint reports many unused strings/resources.
   - **Impact:** Localization, pluralization, accessibility review, and content changes are difficult. The claimed multi-language support is inconsistent.
   - **Fix:** Move visible strings to resources with locale-qualified translations. Use the existing resource files or remove dead resources after migration.

6. **The main screen has no meaningful loading/error/permission state.**
   - **Evidence:** `MainActivity.kt:76-105` initially renders an empty full-screen surface; status relies mainly on a snackbar; HomeScreen’s cloud status is calculated once with `remember`.
   - **Impact:** Users can face a blank screen or stale “Cloud AI Active” label after settings/permission changes.
   - **Fix:** Drive a single Compose screen from observable app state (permissions, overlay/capture/voice readiness, provider availability, model readiness). Make recovery actions explicit.

7. **Launcher themed icons are incomplete.**
   - **Evidence:** lint reports missing monochrome tags across adaptive icon resources.
   - **Impact:** The app icon can render poorly in Android themed-icon launchers.
   - **Fix:** Add monochrome layers for both standard and round adaptive icons.

## P2 — architecture, data, and maintenance

1. **`fallbackToDestructiveMigration()` can silently delete user memory.**
   - **Evidence:** `AppModule.kt:25-27`.
   - **Fix:** Supply real migrations; if a reset is unavoidable, obtain explicit consent and export/delete selectively.

2. **“Clear all memories” does not clearly clear every retained category.**
   - **Evidence:** `SettingsActivity.kt` clears profile/form DAOs, but `MemorySystem.kt` also records `TaskMemoryEntity` and `MemoryVectorEntity`.
   - **Impact:** The button’s label and dialog promise more than the implementation deletes.
   - **Fix:** Delete task history/vectors too, cancel pending extraction, and state exactly what is removed.

3. **UI-map worker does not fulfill its stated background mapping behavior.**
   - **Evidence:** `UIMapWorker.kt:94-99` documents opportunistic mapping; `mapApp` returns unless an already captured frame and current app exactly match.
   - **Impact:** It cannot build maps at install time for its listed apps, and generated plans are only “tap the first six clickable elements,” not goal-aware.
   - **Fix:** Rename/re-scope the feature or design a user-initiated learning flow with clear consent, screen identity validation, and task-outcome labeling.

4. **Static accessibility-service reference is a lifecycle/memory-leak risk.**
   - **Evidence:** lint flags `LumiAccessibilityService.instance`; it is accessed globally by task/worker code.
   - **Fix:** Expose a binder/repository or event stream; do not retain the service instance globally.

5. **Screen capture is forced to a 1280×720 landscape buffer.**
   - **Evidence:** `ScreenCaptureService.kt:102-117` sets `targetW=1280`, `targetH=720` irrespective of device orientation.
   - **Impact:** Portrait phone content is scaled/cropped/distorted, harming VLM coordinates and pHash matches.
   - **Fix:** Capture current display dimensions/orientation, account for insets/rotation, retain source-to-model coordinate transforms, and validate on portrait/landscape/foldable devices.

6. **Version/tooling health needs a planned upgrade rather than opportunistic changes.**
   - **Evidence:** lint warns that Navigation’s custom checks are skipped because its lint API is incompatible, and reports old Android Gradle Plugin/dependencies.
   - **Fix:** Upgrade AGP/Gradle/Kotlin/AndroidX as a tested compatibility set. Re-enable the skipped Navigation lint checks and lock dependency versions in CI.

## Recommended remediation sequence

1. Revoke exposed API keys; purge them from source/history/build artifacts; add secret scanning.
2. Disable auto-tap by default and gate all irreversible actions behind explicit confirmation.
3. Remove mock VLM/TTS production paths; ship only verified capabilities with an honest unavailable state.
4. Fix all seven lint errors and make `lintDebug` a required CI check.
5. Repair task-session cancellation and screen-transition state handling; add state-machine and race-condition tests.
6. Make Hindi/offline model dependencies coherent; fix the failing unit test through a correct implementation, not by weakening the assertion.
7. Implement data minimization/encryption and truthful consent/privacy copy before sending any screen/tree data to cloud providers.
8. Bind UI settings to real state, improve overlay semantics/TalkBack support, and validate physical-device flows across API 29–35.
9. Replace package-wide UI-map fallbacks with screen-verified, user-confirmed guidance.
10. Add CI gates: unit tests, lint with zero errors, dependency/security scan, secret scan, and emulator smoke tests for onboarding/permissions/voice/overlay.

## High-value test matrix to add

- Runtime permission denied/revoked while listening or capturing.
- API 29, 30, 31, 33, and 35 receiver registration and model tier selection.
- Cancel during cloud request, local inference, TTS, auto-tap delay, and screen change.
- Same-app navigation versus package transition; duplicate accessibility events.
- Sensitive-screen detection and confirmation behavior for all irreversible controls.
- Portrait, landscape, display zoom, font scaling, TalkBack, and gesture navigation.
- Offline/no-model, partial-model, failed/corrupt/resumed model download, and no-network paths.
- Provider schema failures, malformed/escaped JSON, rate limits, timeouts, and redacted logs.
- Data-clear verification for profile, form, task, vector, model, and encrypted-key stores.
